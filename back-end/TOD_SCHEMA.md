# 📄 Tree of Debate (ToD) Case Schema

This document defines the new data structure for cases generated by the Tree of Debate framework.
These documents are stored in MongoDB and parsed by `StateLoader`.

## Structure

```json
{
  "_id": "tod_checkin_angry_001",
  "root_operation": "Check-in", 
  "debate_trace": ["Planner: Node 1 created", "Refiner: Expanded context"],
  
  "unity_init": {
    "environment": "env_reception_desk",
    "character_prefab": "char_vip_male_01",
    "initial_animation": "anim_tapping_watch_impatiently"
  },
  
  "agent_init": {
    "persona_name": "Mr. Viktor",
    "system_prompt": "You are Mr. Viktor, a VIP guest. You are extremely impatient because your room is not ready. You will NOT leave the reception desk. You demand to speak to the manager.",
    "knowledge_base": {
      "booking_info": "Booked via direct call, Presidential Suite, Paid 50% deposit.",
      "hotel_policy": "VIPs get immediate check-in or complimentary lounge access."
    },
    "required_tasks": [
      "Trainee calms guest down.",
      "Trainee verifies booking and identity.",
      "Trainee offers lounge access while waiting."
    ],
    "base_tension": 0.5,
    "escalation_rate": 0.2,
    "passing_threshold": 1.0,
    "ending_type": "none"
  },
  
  "transitions": {
    "possible_resolutions": [
      {
        "user_action": "Trainee successfully calms the guest and offers lounge access.",
        "next_case_id": "tod_checkin_angry_lounge_f2"
      },
      {
        "user_action": "Trainee fails to calm the guest or ignores them.",
        "next_case_id": "tod_checkin_angry_manager_f2"
      }
    ]
  }
}
```

## Key Components

1. **`unity_init`**: Stripped down visual information sent to the Unity frontend. No interaction logic is here.
2. **`agent_init`**: Context injected into the LangGraph persona agent.
   - `required_tasks`: List of actions the user must complete to resolve the current situation.
   - `base_tension`: Float (0.0 to 1.0). Initial tension/anger level of the guest. 0.0 is calm, 1.0 is extremely angry/rushed.
   - `escalation_rate`: Float (e.g. 0.2). How much tension increases if the user fails to resolve the task or stalls.
   - `passing_threshold`: The required percentage of tasks completed to proceed (e.g., 1.0 for all tasks, 0.8 for 80%).
   - `ending_type`: Describes if this case ends the branch. Can be `"good"` (successful resolution), `"bad"` (failure/guest leaves), or `"none"` (scenario continues to a next case).
3. **`transitions`**: Defines flexible dynamic branching.
   - `possible_resolutions`: A list of potential user actions and the corresponding `next_case_id`. If `ending_type` is not "none", this can be empty.
